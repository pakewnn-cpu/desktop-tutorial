# Contributing

Thanks for taking an interest! This is a self-taught developer's tutorial repo, and
the goal is simple: keep the process open and make sure the guide actually runs.
Spend a minute reading this before you start — it'll get your contribution merged
faster and keep the repo safe.

## Before you contribute

1. Read the repo's house rules first — they're the baseline for everything here.
2. Before you start, **open an issue** describing what you want to change and
   agree on the direction with me, so we don't do wasted work.
3. Search existing issues first, to avoid duplicates.

## Rules for pull requests

- **One problem per PR** — don't bundle unrelated changes.
- Commit messages follow a conventional format, starting with `feat:` / `docs:` /
  `fix:` / `chore:`, and say clearly what changed.
  - Example: `docs: clarify the Ollama endpoint in 02`
- Keep changes scoped to the issue you're solving.
- Make sure the CI check passes before you open the PR.

## What not to do

- No secrets, keys, personal data, or business data in the repo.
- No spam, ads, or off-topic noise in issues or comments.
- Keep the discussion professional and friendly.

Thanks for helping keep this a clean, useful place. 🙏
