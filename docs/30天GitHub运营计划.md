# 30 天 GitHub 运营计划

> 写给一个「自学、想靠 GitHub 证明自己」的人。
> 目标不是「看起来很努力」，而是**真的在持续做事，并让 GitHub 如实记录它**。

## 先说三句大实话（别被网上带偏）

1. **绿格子不是刷出来的，是「真的提交了」才有。** 一天一个真实的小提交，30 天就是 30 个格子。空提交、假提交 GitHub 能识别，而且没人会信。
2. **没有「免费的 24 小时 AI 打工仔」。** 网上说的「DeepSeek Super Agent 自动修 Bug 提 PR」这类，目前没有一个成熟、开箱即用、还免费稳定的产品。有 AI 助手能帮你写代码、能接进 CI，但**最后一步永远要你自己审**。把它当「实习生」，别当「员工」。
3. **Copilot 有免费版，够用。** 不必一上来就花钱。先免费用起来，真觉得值了再升级。

## 四周主题（一条主线，别贪多）

| 周 | 主题 | 一句话 |
| --- | --- | --- |
| 第 1 周 | 打地基 | 把环境、习惯、账号门面搭好 |
| 第 2 周 | 做内容 | 每天往仓库里加一点真东西 |
| 第 3 周 | 提质量 | 让项目「看起来专业、跑得起来」 |
| 第 4 周 | 走出去 | 让别人能看到你、能和你合作 |

## 每天模板（15–30 分钟，别超过）

每天只做三件事，做完就关电脑：

1. **想 1 分钟**：今天给仓库加什么？（一个命令、一段说明、一个 bug 修复……越小越好）
2. **做 + 提交**：做完立刻 `git commit`，写清楚「今天做了什么」。
3. **推上去**：`git push`，让 GitHub 上能看到。

> 关键：**小步、天天有**。一天一个真实提交，比一周憋一个大的强 10 倍。

## 第 1 周：打地基

- **Day 1**：跑一遍 `bash scripts/setup.sh`，把本地环境搭起来；把 README 里的邮箱换成你自己的。
- **Day 2**：把 4 篇教程（`docs/`）从头读一遍，每篇补一句「我实际踩到的坑」。
- **Day 3**：给仓库加 **Topics**（标签，如 `macos` `ai` `tutorial` `ollama`）和一句**仓库描述**——这是别人搜到你时的门面。
- **Day 4**：配好 GitHub 的 **Pinned 仓库**，把本仓库钉到主页最显眼处。
- **Day 5**：写一份 `CONTRIBUTING.md`（怎么参与本项目），哪怕只写 3 行。
- **Day 6–7**：把本周所有改动整理成一次「v0.1 发布」，在 GitHub 上点 **Release**，写清楚这版有什么。

## 第 2 周：做内容

- **Day 8–10**：每天加一个小脚本到 `scripts/`（比如「一键备份配置」「检查本地模型是否在线」），每个都配一句说明。
- **Day 11–12**：给 02、03 篇教程各加一张**截图**（放 `docs/images/`），图文并茂更专业。
- **Day 13–14**：写一篇 `docs/05-常见问题.md`，收集你这两天遇到的报错和解决办法。

## 第 3 周：提质量

- **Day 15–16**：用 **GitHub Copilot** 把一段写得乱的脚本重构一遍，或让它补一段单元测试。体验「AI 帮你提质量」。
- **Day 17–18**：完善 **CI**（`.github/workflows/ci.yml`）：让它每次提交自动跑检查。看绿勾变多，成就感很足。
- **Day 19–20**：统一提交信息格式（用 `feat:` `docs:` `fix:` 开头），让提交历史「读起来像 changelog」。

## 第 4 周：走出去

- **Day 21–23**：去一个你**正在用的**开源项目，提一个**小** Issue 或 PR（哪怕只是改个错别字、补个文档）。这是「参与开源」最真实的姿势。
- **Day 24–25**：在 README 顶部加一句「我最近在学什么 / 在做什么」，让主页有「活人感」。
- **Day 26–28**：把这份 30 天计划本身，当成一个可复用的模板，写进 `docs/`，并邀请别人 fork。
- **Day 29–30**：写一份「30 天复盘」：做了什么、卡在哪、下 30 天做什么。发布成 Release。

## 绿格子（贡献图）怎么长出来

- **唯一靠谱的办法：真的、小步、天天提交。** 一个提交 = 一格。
- 想让格子更密：把「写文档」「改 README」也算提交，这些也是贡献。
- **别做的事**：空提交、`--allow-empty` 刷格子、批量补历史。GitHub 能识别，且没人会信。
- **让格子「好看」**：提交信息写清楚（如 `docs: 补充 02 篇的截图说明`），点进历史能看出你在成长，比格子数量更有说服力。

## 工具篇（诚实版）

### 1. GitHub Copilot / Copilot Chat
- **是什么**：GitHub 官方的 AI 编程助手，能在 IDE 里补代码、解释代码、重构。
- **怎么用**：在 VS Code 等 IDE 里装 Copilot 插件；选中一段乱代码，让它重构；或让它生成测试。
- **Agent 模式**（旧名 Copilot Workspace / Copilot agent）：给它一个任务，它自动改多个文件、跑命令。
- **钱**：**有免费版（Copilot Free）**，个人够用；Pro 约 $10/月。先免费用，值了再升。

### 2. 「自动修 Bug、自动提 PR」的 AI Agent
- **实话**：目前**没有**一个成熟、开箱即用、还免费稳定的「DeepSeek Super Agent 式」产品，能 24 小时无人值守替你修 Bug 提 PR。
- **真实可用的替代**：
  - **编码 Agent**（如 Codex 命令行、Claude 等）：你给它仓库，它帮你分析 Issue、写修复，但**最后要你自己审、自己合并**。
  - **开源 Agent 项目**（如 Aider、Cline、OpenHands 等）：可本地或服务器部署，监听仓库、起草 PR，同样需要你把关。
  - **GitHub 自带的 coding agent**：在 Issue 上 @ 它，它能起草 PR。
- **定位**：把它当「24 小时实习生」——它能干粗活，但**关键决定和最终合并永远是你**。

### 3. GitHub Actions（自动化，真香）
- **是什么**：每次提交 / PR 自动跑一段流程。公共仓库**免费额度很足**。
- **能干嘛**：自动跑代码检查、自动更新文档、自动打版本、自动回复模板。
- **怎么开始**：本仓库已有一个 `ci.yml` 在跑。你可以让它每次提交自动检查脚本语法——这就是「看起来很专业」的第一步。

## 常见坑

- **提交信息写「update」「修改」**：等于没写。写清楚「改了什么」。
- **一上来就搞大项目**：先小步，先完成，再扩大。
- **只提交不推送**：GitHub 上看不到，等于没做。每天记得 `git push`。
- **被「AI 全自动」带偏**：没有免费的完美自动化，自己把关永远最重要。

## 30 天结束，你会得到

- 一个**持续 30 天、每天真实提交**的仓库（绿格子是真实的）。
- 一套**能跑起来、有 CI、有文档**的项目。
- 一次**真实的开源参与**（Issue 或 PR）。
- 一份**复盘**，清楚知道下 30 天做什么。

> 记住：GitHub 上最打动人的，不是格子多，而是**看得出一个人真的在持续做事**。
